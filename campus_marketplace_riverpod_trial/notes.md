# State Management Decision

## 1. Search Box — ใช้ Local State

ช่องค้นหาเก็บค่าที่ผู้ใช้พิมพ์ไว้ในตัว Widget เอง โดยใช้ `ConsumerStatefulWidget` และ `setState()`

### เหตุผล

ค่าที่ผู้ใช้พิมพ์ในช่องค้นหาถูกใช้เฉพาะในหน้านี้ และไม่มีหน้าอื่นต้องนำค่าการค้นหาไปใช้ต่อ ดังนั้นไม่จำเป็นต้องเก็บไว้ใน Riverpod

การใช้ `setState()` จึงเป็นวิธีที่ง่ายและเหมาะสมกว่า เพราะเป็นข้อมูลที่มีผลเฉพาะกับ UI ของหน้านี้เท่านั้น

> **สรุปง่าย ๆ:** ผู้ใช้พิมพ์อะไรในช่องค้นหา ก็ให้หน้านี้จัดการข้อมูลเอง ไม่จำเป็นต้องให้ทั้งแอปรับรู้

---

## 2. Clear All Favorites — ใช้ App State ด้วย Riverpod

ข้อมูลรายการโปรดเป็นข้อมูลที่ส่วนอื่น ๆ ของแอปอาจต้องใช้งานร่วมกัน จึงจัดการเป็น **App State** ด้วย `FavoritesNotifier` และ `StateNotifierProvider`

### การแสดงผลของ UI

ใช้

```dart
ref.watch(favoritesProvider)
```

เพื่อดูข้อมูลรายการโปรดในปัจจุบัน

เมื่อรายการโปรดมีการเปลี่ยนแปลง UI จะถูกสร้างใหม่โดยอัตโนมัติ เช่น ปุ่ม **Clear All** จะแสดงเฉพาะเมื่อมีรายการโปรดอยู่

### การล้างรายการโปรด

เมื่อผู้ใช้กดปุ่ม **Clear All** และยืนยันใน Dialog แล้ว ใช้

```dart
ref.read(favoritesProvider.notifier).clear()
```

เพื่อสั่งให้ `FavoritesNotifier` ลบรายการโปรดทั้งหมด

> **สรุปง่าย ๆ:** Favorites เป็นข้อมูลที่หลายส่วนของแอปสามารถใช้งานร่วมกันได้ จึงให้ Riverpod เป็นคนจัดการ ส่วนปุ่ม Clear All มีหน้าที่สั่งให้ระบบลบรายการโปรดทั้งหมด

## 3. ทำไมถึงเลือกใช้ State ต่างกัน?

| ข้อมูล / การทำงาน | วิธีจัดการ | เหตุผล |
|---|---|---|
| Search Query | `setState()` | ใช้เฉพาะในหน้านั้น ไม่จำเป็นต้องแชร์ให้ส่วนอื่น |
| Favorites | Riverpod | เป็นข้อมูลที่หลายส่วนของแอปสามารถใช้งานร่วมกันได้ |
| แสดงปุ่ม Clear All | `ref.watch()` | ต้องติดตามว่า Favorites มีข้อมูลหรือไม่ เพื่ออัปเดต UI |
| กด Clear All | `ref.read()` | เป็นการสั่ง Action เพียงครั้งเดียว ไม่จำเป็นต้องติดตามการเปลี่ยนแปลง |

---

## 4. หลักการจำง่าย ๆ

- **ข้อมูลใช้เฉพาะใน Widget เดียว → `setState()`**
- **ข้อมูลที่ต้องแชร์หลายส่วนของแอป → Riverpod**
- **ต้องการดูและติดตามการเปลี่ยนแปลงของ State → `ref.watch()`**
- **ต้องการสั่งให้ State เปลี่ยนหรือเรียก Action → `ref.read()`**

---

## 5. แนวคิดโดยรวม

การเลือกว่าจะใช้ `setState()` หรือ Riverpod ไม่ได้ขึ้นอยู่กับว่าอันไหนใหม่กว่าหรือดีกว่า แต่ขึ้นอยู่กับว่า **ข้อมูลนั้นมีขอบเขตการใช้งานกว้างแค่ไหน**

ถ้าข้อมูลมีผลเฉพาะกับ Widget เดียว การใช้ `setState()` จะเรียบง่ายและเพียงพอ

แต่ถ้าข้อมูลต้องถูกใช้งานหรือเปลี่ยนแปลงจากหลายส่วนของแอป เช่น Favorites ก็ควรใช้ Riverpod เพื่อให้จัดการ State ได้เป็นระบบ และสามารถติดตามการเปลี่ยนแปลงจากส่วนต่าง ๆ ของแอปได้
